# 3D Avatar Maker package rules for coding agents

These rules apply to changes under `packages/3d-avatar-maker/`. They add to the repository rules in the
root `AGENTS.md`, `.github/agents/chai-workflow.md` and `CONTRIBUTING.md`; they do not replace them. What
the package does is in `README.md`; what's built and what's next is in `docs/PLAN.md`. Keep both current
with every change.

## Standing rules

- This package is separate from Wanderworld. Never edit `packages/wanderworld/` or Wanderworld's build
  scripts for this package's sake, and never read Wanderworld's kit at run time. Code or files wanted from
  there are copied here and changed here.
- Humans only for now. Every feature works without AI; anything that calls a model is off until the user
  turns it on, has its own switch, and says what it sends.
- Only CC0 or CC-BY material: MakeHuman's data and its community packs (read as data; MakeHuman's GPL code
  is never run or copied), the Vitruvian character for CharMorph (CC0, read as data; CharMorph's GPL code is
  never run or copied) and what is made here. The main kit stays CC0, so a saved avatar is free to share;
  CC-BY items go in the separate asset packs, with their authors credited there. Check each item's own files
  as well as its catalogue, and leave out any whose files say otherwise (AGPL headers): `docs/MAKEHUMAN-PACKS.md`
  is the item-by-item list. Anything under another licence: ask first.
- Anything made in Blender is credited to ThatOneCan in `kit/CREDITS.md` and the README's credits, naming
  what it is, and is released as CC0.
- The maker writes nothing to the Engine. An avatar leaves as a file the user saves.
- Every control says what it changes. Sliders have the body's own shape in the middle.
- Version bumps are +0.0.01 with a two-digit last part (0.1.00, 0.1.01, … 0.1.99, 0.2.00), one for every
  committed rebuild, each with a `CHANGELOG.md` entry. Bump `VERSION` in
  `scripts/build-3d-avatar-maker-package.mjs` before building, or the build overwrites the last zip.
- Open no issue or pull request and push nothing but the dev catalog branch until the user asks.

## Changing the models

The models are made by headless Blender scripts and then packed into the kit. Set `BLENDER` to the Blender
executable (Blender 5.3 is what the scripts were written with) and keep that path out of committed files.

```bash
"$BLENDER" --background --factory-startup --python packages/3d-avatar-maker/assets/scripts/make_avatar.py
node scripts/build-3d-avatar-maker-kit.mjs
node scripts/build-3d-avatar-maker-masks.mjs
```

The first writes the models into `assets/models/`; the second packs them into `kit/avatar` and
`kit/wardrobe` (ffmpeg on `PATH`, or `FFMPEG`); the third makes each body's paint masks
(`kit/avatar/avatar-<sex>-masks.png`: where the nails and lips are in the skin picture, so `src/skin.js`
colours them with a clean edge), and the makeup mask (`kit/avatar/avatar-makeup-masks.png`, from the
community packs' made-up skins; kept as it is when MakeHuman's pictures aren't found), and each body's hair
masks (`kit/avatar/avatar-<sex>-hair-masks-<n>.png`: where its facial hair grows and the kit's hair styles lie,
so the skin under hair is painted in the hair's colour). Run the third whenever a body or the hair is repacked. The packer reads and writes only under
`packages/3d-avatar-maker/`. The body script reads MakeHuman's data from the user's asset folder
(`MAKEHUMAN_DATA` and `MAKEHUMAN_ASSETS`, else `_planning/Wanderworld asset packs/MakeHuman`).

The Realistic body is built apart from the other two, from the Vitruvian character for CharMorph (CC0), which
lives outside the repository (`VITRUVIAN_DATA`, else `_planning/Wanderworld asset packs/Vitruvian/CharMorph-Vitruvian-main`):

```bash
"$BLENDER" --background --factory-startup --disable-autoexec --python packages/3d-avatar-maker/assets/scripts/make_realistic.py
node scripts/build-3d-avatar-maker-kit.mjs realistic
```

The first writes `assets/models/realistic-*.glb`, `realistic-body.json` and `assets/textures/realistic/`
(`-- body`, `-- textures`, `-- hair` or `-- brows` builds one of them; ffmpeg on `PATH`, or `FFMPEG`); the second packs
them into `kit/avatar/realistic-*` and leaves the rest of the kit as it is. `src/realistic.js` builds that
body in the maker; nothing in it reads the other bodies' files, and `BODIES` in `src/looks.js` stays the
kit's two, which the clothes, hair and presets are made for. Its sliders are named in three places that must
agree: `SLIDERS` in the script, `REALISTIC_SHAPES` in `src/looks.js`, and the keys in its packed file.

The face and body sliders are pairs of shape keys, `<slider>.lo` and `<slider>.hi` (`FACE_DETAIL`,
`BODY_DETAIL`, `BREAST_DETAIL` in `make_avatar.py`, the same names in `src/looks.js`). Only the skin and eyes
carry them in the model; the pieces beside the body (brows, lashes, beards, underwear, horns, tail) and the
hair and clothes get them at run time from the skin (`src/avatar.js` `carried`). Giving every piece every key
took the model file past 85 MB; keep model files well under GitHub's 100 MB limit. Run the body script one
body per Blender process (`-- male`, then `-- female`): a second body in the same process once failed to
overwrite an eye picture the first had just written.

Judge model work against the avatar's bar: it is what the user looks at all the time, so check renders up
close, in the maker's own view and on the check page, not only in Blender.

## Checking a change

```bash
node tests/3d-avatar-maker.regression.mjs
npm run check
node packages/3d-avatar-maker/dev/serve.mjs
```

On the test page (`http://127.0.0.1:5197/`), build an avatar and save it. On the check page
(`/viewer?file=/dev/out/<name>.glb`) the same file is loaded the way the Engine's 3D Avatars agent loads a
GLB: bones found by name, arms straightened, face shapes driven by name.

After a change to the animations, the clothes' layers or the springs, look over the motions page: it draws
one avatar through every animation, frame by frame, on a sheet kept in `dev/out/`.
`/motions?body=female&motions=walk,sit&view=legs` narrows it; `faces=1` draws the faces; `outfit=` and
`look=` (a look as JSON) dress it. The notes at the top of `dev/motions.js` list the rest.
